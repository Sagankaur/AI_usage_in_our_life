# Milestone AI Playbook

Use this as the main handout for students.

## Milestone 1: User Requirements

Course deliverables:

- Primary, secondary, and tertiary users.
- Interview or observation study evidence.
- Pain points and concerns.
- SMART user stories in the format:
  - As a [type of user],
  - I want [an action],
  - So that [a benefit/value].

Good AI use:

- Clean interview notes.
- Separate evidence from interpretation.
- Identify possible user roles.
- Check whether user stories follow SMART guidelines.
- Find vague, oversized, or unsupported stories.

Bad AI use:

- Inventing interviews.
- Inventing user quotes.
- Asking users feature-leading questions.
- Turning weak evidence into fancy unsupported features.

## Milestone 2: Scheduling and Design

Course deliverables:

- Component design.
- Basic class diagram.
- Database design diagram.
- Sprint schedule.
- Scrum meeting schedule and minutes.
- Gantt chart screenshot.
- Kanban board screenshot.
- Frontend page screenshots.
- Frontend code ZIP with README.

Good AI use:

- Review whether components match user stories.
- Critique class diagrams for missing relationships.
- Convert user stories into sprint tasks.
- Draft scrum minutes from real meeting notes.
- Check frontend pages against user workflows.
- Draft README run instructions.

Bad AI use:

- Creating design diagrams disconnected from Milestone 1 stories.
- Inventing scrum meetings that did not happen.
- Generating UI pages that look complete but do not support the workflows.

## Milestone 3 and 4: Sprint 1 and Sprint 2

Course deliverables:

- List of APIs created.
- List of APIs integrated.
- Description of API endpoints.
- Swagger-compatible YAML for APIs created by the dev team.
- Backend API implementation.
- Extensive test cases in the required format:
  - API being tested
  - Inputs
  - Expected output
  - Actual output
  - Result: Success/Fail
- pytest code and output.
- User feedback and plan for next sprint.

Good AI use:

- Map user stories to API endpoints.
- Draft Swagger-compatible YAML.
- Find missing error handling in YAML.
- Design API test cases before coding.
- Generate pytest skeletons.
- Review whether implementation matches YAML and user stories.
- Summarize real user feedback into next-sprint actions.

Bad AI use:

- Writing APIs before agreeing on YAML and tests.
- Submitting tests without actual output.
- Hiding failed tests.
- Adding GenAI or external APIs without documenting them.

## Milestone 5: Final Submission

Course deliverables:

- Video presentation.
- Presentation slides.
- Complete working code ZIP.
- README with run instructions.
- Final PDF report compiling all milestones and sprints.
- Tools and technologies used.
- Issue tracking and code review screenshots.

Good AI use:

- Build a final consistency checklist.
- Review README instructions for Windows, Ubuntu, and macOS.
- Draft presentation structure.
- Summarize issue-tracker activity from real data.
- Review final report for gaps against the rubric.

Bad AI use:

- Claiming tools or technologies that were not used.
- Inventing issue tracker activity.
- Submitting code students cannot explain.
